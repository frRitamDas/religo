# Contributing to ReliGo

Thank you for helping improve ReliGo. Contributions should make the project more reliable, accessible, understandable, and useful to people saving media from supported public links.

## Before proposing a change

- Search existing issues and discussions for related work.
- For a substantial feature, open an issue first so the scope can be discussed.
- Keep pull requests focused and describe the user-visible effect, the implementation approach, and how you tested it.
- Never include private media URLs, access tokens, secrets, or personal information in public issues or test fixtures.

## Project scope

ReliGo is intended for processing freely accessible media links where the user is allowed to save the content. Changes should respect source-platform terms, applicable law, and content creators' rights.

When reporting a problem, include the source service, a reproducible public example where appropriate, expected behavior, actual behavior, and relevant error output. Redact anything sensitive.

## Code quality

- Follow the conventions in the surrounding files.
- Keep compatibility in mind when changing API responses and shared types.
- Update documentation and release notes when behavior or configuration changes.
- Test the affected frontend or API package before submitting a pull request.

## Licensing and attribution

ReliGo is derived from the open-source [Cobalt project](https://github.com/imputnet/cobalt). Preserve applicable upstream copyright notices, licence terms, and attribution. The web frontend and API retain their respective licence files; review both before redistributing changes.

## Pull requests

A good pull request explains **what changed**, **why it helps users**, and **how it was verified**. Be respectful during review; focused feedback helps us ship a better ReliGo.
