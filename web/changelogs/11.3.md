## Renewed API and server rollout

ReliGo's API has been renewed for version 11.3 with aligned package metadata, a ReliGo startup banner, and consistent server response information. The website and API both identify as **11.3**, maintained by **Ritam Das**.

The Render service is configured for deployment from the `main` branch. Instance count, concurrency, and capacity continue to depend on the active Render plan and service configuration; version labels alone do not imply a hosting-plan upgrade.

## What changed for users

- **New ReliGo mark:** replaces the old in-app logo with a custom blue-violet R mark and matching SVG favicon/app metadata.
- **One-tap API copy:** copy the configured ReliGo API address from About without selecting the URL manually.
- **Complete project card:** website version, API version, developer credit, release label, API endpoint, and source links are grouped together.
- **Cleaner support route:** source-code and issue-reporting links lead to the ReliGo repository. Unrelated payment channels are not presented as ReliGo donations.
- **Clearer privacy notes:** the About section explains local processing, server-side processing, temporary tunnel information, and hosting-provider limitations instead of promising universal zero logging.
- **Refined release notes:** custom 11.3 artwork, clearer headings, responsive text sizes, and better long-link wrapping improve reading on smaller screens.
- **Consistent navigation:** historical update links are routed to ReliGo's repository wherever a corresponding resource is available.

## Compatibility and availability

The API response retains a legacy `cobalt` compatibility field so previously deployed frontend bundles can continue to read cached server information while updating. This field is technical compatibility metadata, not the public product identity. Applicable open-source licenses, upstream attribution, and copyright notices remain in the repository.

ReliGo supports YouTube links, but successful retrieval can still depend on upstream anti-bot checks, regional restrictions, the requested media, and hosting conditions. The infrastructure refresh does not guarantee every source will always work.
